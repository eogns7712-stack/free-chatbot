# v8: 같은 주제의 상태 구분

## 변경 배경과 범위

초기 v7은 첫 답변 반복 학습을 제한해 후속 정보·주제 전환을 유지하려는 실험이었다. 실제 화면과 상태 진단16개에서 단독 발화도 계획·진행·완료·취소를 혼동했다. 이번에는 상태 표현 학습을 추가한다. 이전 문맥만이 원인이라고 확정하지 않는다.

기존 v6 데이터435개를 그대로 보존하고48개를 추가해483개다. 산책·영화 각각 네 상태에 세 표현을 쓰며, 단독 발화와 계획→장소/제목→현재 상태의3턴을 짝지었다. 신규3턴은 마지막 assistant만 학습한다. 앞선 계획 문맥을 반복 학습하지 않고 현재 상태 반응을 보강하려는 목적이다. 단문은 유일한 assistant를 학습한다.

검증101개는 기존93+신규 문맥8개다. 기존 학습기가 단문 검증 손실을 허용하지 않아 신규 단문 검증8개는 probes에만 넣었다. 비교109개는 기존93+신규16개, probes235개다. 신규 검증·비교 표현은 학습과 다르나 상황 구조를 공유한다. 기존 state_transition_v8.json 문장은 학습에서 제외했다. 의미적으로 유사한 예시는 있다.

## 실행

이번에는 실제 화면에서 사용한 v7/epoch-02에서 추가 학습한다. 원본 모델에서 다시 시작한 v5/v6 실험과는 시작점이 다르다. epoch-00이 현재 모델 기준이며 새 결과와 이전 전체 검증 손실을 직접 비교하지 않는다. 옵티마이저는 새로 생성한다. 기존 첫 답변 제한 정책을 유지한다.

프로젝트 루트:

```powershell
.\.venv\Scripts\python.exe experiments/train_first_reply_cap_v7.py --source artifacts/first-reply-cap-v7/epochs/epoch-02 --data data/state_contrast_v8 --output artifacts/state-contrast-v8 --epochs 3 --learning-rate 0.0001
```

CPU4스레드·배치1·시드42·3회로 제한한다. 30분 완료는 보장하지 않는다. 기존 출력을 덮어쓰지 않으며 resume은 지원하지 않는다. --check-only는 학습 없이 마스킹만 검사한다. 실행 확인 결과 학습 목표 토큰은 회차당8868개에서 첫 답변 제한 후5938개다. 기존 last_assistant 설정과 모든 후속 목표는 보존한다.

## 평가와 종료 기준

검증용 신규 상태16개를 단독/문맥으로 나눠 판단한다. 계획·진행·완료·취소에 맞는 이해 가능한 관련 응답이면 통과한다. 취소한 것을 했다고 하거나 하라고 하면 실패, 관련 주제이지만 시점을 혼동하면 부분이다. 이미 알려 준 장소나 제목 재질문도 부분이다. 정확 일치는 보조 지표다.

회차 선택에는 검증 손실과 검증 문답의 실제 rollout을 사용한다. 선택 후 신규 비교16개와 고정된 기존 상태 진단16개를 확인한다. 기존 단문·후속·전환·3턴 공통 probes203개에서 새로운 실패가 생기는지 확인한다. 새 상태 표현만 맞고 기존 기능이 퇴보하면 기준 모델 교체를 보류한다.3회 후 같은 조건으로 자동 연장하지 않는다.

아직 본 학습은 실행하지 않았다. 데이터 생성·중복·역할·길이·마스킹 검사는 통과했다. 새 기능은 두 주제의 네 상태에 한정되며 자유 대화 완성이나 모든 상태 전이 조합을 뜻하지 않는다.
