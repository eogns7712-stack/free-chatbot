# v6: 후속 정보와 주제 전환 구분

## 변경 이유

초기 v5는 마지막 답변만 학습했고, 후속 정보 반영은 개선됐지만 첫 응답 오류가 남았다. v5-all-assistant에서는 첫 답변도 학습해 신규 문답 흐름은 개선됐으나 기존 영화→산책·식물 등의 전환 실패가 생겼다. 이번에는 같은 질문 뒤에 질문에 대한 답과 새 주제 발화를 짝지어 구분하도록 보강한다. 원인을 확정한 것이 아니라 데이터 보강 가설을 시험한다.

기존 v5-all-assistant 387개를 내용·순서·손실 설정 그대로 보존하고48개(후속24·전환24)를 추가했다. 총435개다. 신규 예시는 두 assistant 답변의 본문과EOS를 학습한다. 기존 last_assistant 설정은 그대로 유지한다. 검증93개(기존69+신규24), 비교93개(기존69+신규24), probes203개다.

영화·식물·산책의 세 직전 문맥마다 나머지 네 주제로의 전환과 후속 정보를 대비한다. 검증·비교는 다른 후속 문형·이름을 쓰지만 첫 문맥은 학습과 공유한다. 사용자 발화 전체 순서의 정규화 정확 중복은 검사했으며 의미적 독립성을 보장하지 않는다. 기존 실패 평가 문장을 학습에 복사하지 않는다.

## 실행

이전 추가 학습 모델에서 이어가지 않고, v5와 같은 three-turn-flow-v4/epoch-06에서 시작한다. 구조·토크나이저·시드42·CPU4스레드·배치1·학습률0.0001·3회를 유지한다. 데이터가 늘어 처리량과 시간은 달라진다.

프로젝트 루트에서:

```powershell
.\.venv\Scripts\python.exe train_three_turn_v4.py --source artifacts/three-turn-flow-v4/epochs/epoch-06 --data data/followup_switch_v6 --output artifacts/followup-switch-v6 --epochs 3 --learning-rate 0.0001
```

출력이 있으면 중단하며 덮어쓰지 않는다. resume은 지원하지 않는다. 3회 후 자동 연장하지 않는다. 30분 내 완료는 실측 전이므로 보장하지 않는다. 모델과 데이터 원본은 보존한다.

## 비교 방법과 종료 기준

epoch-00이 학습 전 기준이다. 같은 회차의 v5-all-assistant와 공통155개 probes를 ID로 맞춰 비교한다. 검증 구성이 달라 전체 검증 손실을 이전 실험 수치와 직접 비교해 우열을 정하지 않는다.

검증용 신규24개에서 후속12·전환12를 따로 평가하고, 같은 pair_id의 두 흐름을 모두 처리하는지도 기록한다. 정답 문맥의 answer와 실제 생성 문맥의 rollout_turns를 구분한다. 정답 문장 정확 일치만으로 판정하지 않는다. 이미 정보를 받았는데 재질문하면 부분, 명확한 주제 이탈은 실패다.

기존 신규 정보 반영 문답12개 및 단문·2턴·3턴 회귀에서도 새로운 실패를 확인한다. 검증으로 회차를 고른 다음 비교용24개를 확인한다. 이미 반복해서 본 기존 결과는 개발 평가다. 후속 정보 반영과 주제 전환을 함께 유지하지 못하면 기준 모델 교체를 보류한다. 단일 예시 성공이나 낮은 손실을 자유 대화 달성으로 해석하지 않는다.

별도 시나리오: evaluation/followup_switch_v6.json. 기존 평가기를 --scenarios와 --model, 새 --output으로 지정해 재실행할 수 있다. 회차별 probes에도 같은 새 문답이 있으므로 우선 저장된 결과를 확인한다.

생성기: experiments/build_followup_switch_v6.py. 검사 요약과 원본 학습 해시: build_report.json. 기존435개 데이터 생성 후 덮어쓰는 동작은 제공하지 않는다.
